# CronWork v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** App Android con cuenta atrás diaria, bolsa de horas, histórico, avisos y widget; APK publicado en GitHub Releases.

**Architecture:** Dos módulos Gradle. `:core` es Kotlin/JVM puro con todo el cálculo (se prueba sin Android). `:app` es Android (Compose, Room, DataStore) y delega todo el cálculo en `:core`. Un único `TimerController` es el sitio por el que pasan iniciar/parar/ajustar y que sincroniza notificación, alarmas y widget.

**Tech Stack:** Kotlin 2.0.21, AGP 8.7.3, Gradle 8.14.3 (wrapper), JDK 17 en CI, Compose BOM 2024.12.01 + Material 3, Room 2.6.1 + KSP 2.0.21-1.0.28, DataStore Preferences 1.1.1, JUnit 4.13.2, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-02-cronwork-design.md`

## Global Constraints

- minSdk 26, compileSdk 35, targetSdk 35. `applicationId = "com.cronwork"`.
- Textos de la interfaz en español.
- Defaults: jornada 450 min (7:30), laborables L–V, pausa computable desactivada / 30 min / umbral 360 min, aviso de olvido 4 h (0 = off).
- Todo el tiempo se guarda como `Instant` (epoch millis); fechas como `LocalDate` (epochDay). Zona: `ZoneId.systemDefault()` inyectada, nunca leída dentro de `:core`.
- `:core` no depende de Android. Ningún cálculo de horas fuera de `:core`.
- Sin Hilt: contenedor manual `AppContainer` en `CronWorkApp`.
- Entorno local: no hay SDK de Android (dl.google.com bloqueado). Localmente solo se verifica `:core` con `gradle :core:test`. Las tareas Android se verifican con el workflow de CI (requiere poder hacer push).

## Review Focus

1. **Doble "Parar"** (notificación y widget casi a la vez) → el segundo no hace nada; nunca hay dos tramos abiertos ni un tramo cerrado dos veces. Test en Task 4.
2. **Cambio de hora (25-oct-2026, día de 25 h en Madrid)** → las duraciones salen de `Instant`, un tramo 01:00–04:00 local cuenta 4 h. Test en Task 1.
3. **Ajuste negativo mayor que lo trabajado** → el día queda en 0 y `adjustmentClamped = true`. Test en Task 1.
4. **Contador en marcha al pasar medianoche** → el tramo pertenece al día de inicio, se marca `crossesMidnight`, el día nuevo empieza en 0. Test en Task 1 y Task 4.
5. **Editar un tramo con fin anterior al inicio o solapado con otro** → se rechaza con error visible. Test en Task 4.

**Interfaces:**
- Consumes: Tasks 1–2.
- Produces:
  ```kotlin
  // core
  sealed interface EditError { data object EndBeforeStart : EditError; data object Overlaps : EditError; data object InFuture : EditError }
  object SessionRules {
      fun validate(edited: Session, others: List<Session>, now: Instant): EditError?
      fun canStart(sessions: List<Session>): Boolean   // false si hay uno abierto
  }
  // app
  class WorkRepository(db: CronWorkDatabase) {
      val sessions: Flow<List<Session>>; val adjustments: Flow<List<Adjustment>>; val specials: Flow<List<SpecialDay>>
      suspend fun openSession(): Session?
      suspend fun startSession(at: Instant): Boolean        // transacción: no-op si ya hay uno abierto
      suspend fun stopOpenSession(at: Instant): Boolean     // transacción: no-op si no hay abierto
      suspend fun upsertSession(s: Session); suspend fun deleteSession(id: Long)
      suspend fun addAdjustment(a: Adjustment); suspend fun deleteAdjustment(id: Long)
      suspend fun upsertSpecialDay(d: SpecialDay); suspend fun deleteSpecialDay(date: LocalDate)
  }
  class SettingsRepository(context: Context) { val settings: Flow<Settings>; suspend fun update(transform: (Settings) -> Settings) }
  interface TimerSideEffects { suspend fun sync(state: TimerState) }  // notificación + alarmas + widget
  data class TimerState(val running: Boolean, val runningSince: Instant?, val today: DaySummary,
      val weekBalanceSeconds: Long, val totalBalanceSeconds: Long)
  class TimerController(repo: WorkRepository, settings: SettingsRepository, effects: List<TimerSideEffects>, clock: Clock, zone: () -> ZoneId) {
      val state: Flow<TimerState>
      suspend fun toggle(); suspend fun start(); suspend fun stop(at: Instant? = null)
      suspend fun adjust(date: LocalDate, minutes: Int, note: String?)
      suspend fun editSession(s: Session): EditError?
      suspend fun refresh()   // recalcula y llama a todos los effects
  }
  ```
  Toda mutación llama a `refresh()` al final. `start/stop` usan `@Transaction` en el DAO para que dos llamadas concurrentes no dupliquen (Review Focus 1).
